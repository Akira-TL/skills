# 通用 Word 文档生成 Skill

## 一、目标

本 Skill 用于直接生成可交付的 Word 文档，而不是先生成一份带有 Markdown 视觉习惯的内容，再将其机械转换为 DOCX。Agent 必须按 Word 的文档模型组织内容，即使用节、页面、样式、段落、制表位、表格、题注、分页控制、页眉页脚和字符级格式完成排版。

生成结果应当像人工在 Word 中认真排版的正式文档：文字颜色统一，字体层级稳定，段落连续，表格简洁，分页合理。插入的照片、科研图、截图、数据图表和其他图片可以保留原始或具有信息意义的颜色；标题、正文、表格、形状、边框、页眉页脚和装饰元素等非图片内容默认不得使用彩色。文档不得出现彩色标题、彩色表格、彩色形状、渐变底纹、卡片式模块、灰色引用框、Markdown 符号、无意义图标或演示文稿式短句堆砌。

本 Skill 不依赖任何原始模板文件。除非用户明确提供并要求沿用模板，否则必须从空白 DOCX 创建文档，并建立完整的 Word 原生样式体系。

## 二、指令优先级

排版时依次遵循以下优先级：用户本次明确要求最高；用户提供的正式格式规范或目标期刊规范次之；用户提供的参考文档视觉风格再次；文档类型对应的默认版式再次；本 Skill 的通用默认值最低。

不得因为某份旧模板曾经出现过某个学校、单位、封面、评分表或固定字段，就将这些元素带入新的通用文档。

## 三、Word 原生生成原则

### 3.1 不以 Markdown 作为版式中间层

Markdown 可以用于理解内容结构，但不能成为 DOCX 的直接视觉来源。生成 Word 前，必须将输入内容解析为语义对象，例如文档标题、副标题、作者信息、摘要、关键词、一级标题、二级标题、正文段落、长引文、图、图题、表、表题、表注、公式、脚注和参考文献。

随后使用 Word 原生样式分别渲染这些语义对象。禁止把 Markdown 标记保留在文档中，也禁止按照网页 CSS 或聊天界面的视觉样式生成 Word。

下列 Markdown 痕迹在最终 DOCX 中不得可见：`#`、`##`、`###`、`**`、`__`、单独的 `*`、反引号、代码围栏、`>`、`---`、管道表格分隔符以及 Markdown 链接语法。

### 3.2 使用样式，不使用零散直接格式

必须创建并使用稳定的 Word 样式，例如“文档标题”“副标题”“一级标题”“二级标题”“三级标题”“正文”“摘要”“关键词”“图题”“表题”“表注”“参考文献”。同类段落必须共用样式，不得逐段随机设置字体、字号、颜色和间距。

字符级格式只用于确有语义差异的局部内容，例如斜体学名、斜体统计符号、上标、下标、加粗术语或真正的超链接。不得通过把每句话拆成大量 run 来制造无意义的格式差异。

### 3.3 图片与非图片内容的颜色边界

除非用户明确要求品牌色、彩色表格或其他彩色设计，所有 Word 原生非图片内容只能使用黑色、白色及必要灰阶。全文文字必须为纯黑色；标题、正文、表格文字、单元格底纹、边框、页眉、页脚、题注、超链接、文本框、形状、SmartArt、页面背景和装饰元素均不得自动使用蓝色、紫色、绿色、橙色或其他彩色强调。

不得使用彩色渐变、阴影、发光、描边、WordArt、彩色文本框、彩色页面背景、彩色章节卡片、装饰性图标、彩色侧边栏或大面积装饰底纹。必要的浅灰底纹或深灰边框只能用于提高层级辨识和打印可读性，不得形成彩色视觉系统。

作为图片对象插入文档的照片、科研图、显微图像、截图、地图、数据可视化、流程图和示意图允许保留其原始颜色或具有信息区分意义的颜色。不得为了统一文档外观而强制转为灰度，也不得擅自降低图片饱和度、重新着色或删除图片中的颜色信息。

颜色判断以 Word 对象类型为准：导出后作为图片插入的数据图表、流程图和示意图可以使用颜色；使用 Word 原生图表、形状、文本框或 SmartArt 构建的可编辑对象属于非图片内容，默认只能使用黑色、白色及必要灰阶。只有用户明确要求时，才可为这些非图片对象引入彩色。彩色图片用于打印时，应同时通过线型、点型、纹理、标签或直接标注保证灰度打印仍可辨识。

## 五、默认样式体系

### 5.1 通用正式文档样式

| 语义 | 默认格式 |
|---|---|
| 文档标题 | 黑体，二号或小二，18 pt，黑色，加粗，居中，段前 0，段后 18 pt，与下段同页 |
| 副标题 | 宋体或楷体，小三，15 pt，黑色，居中，段后 12 pt |
| 作者或单位信息 | 宋体，小四，12 pt，黑色，居中，段后 12 pt |
| 一级标题 | 黑体，三号，16 pt，黑色，左对齐，段前 18 pt，段后 8 pt，与下段同页 |
| 二级标题 | 黑体，四号，14 pt，黑色，左对齐，段前 14 pt，段后 6 pt，与下段同页 |
| 三级标题 | 黑体或楷体，小四，12 pt，黑色，左对齐，段前 10 pt，段后 4 pt，与下段同页 |
| 正文 | 中文宋体、西文 Times New Roman，小四，12 pt，黑色，两端对齐，首行缩进 2 字符，1.5 倍行距 |
| 摘要 | 中文楷体、西文 Times New Roman，五号，10.5 pt，黑色，两端对齐 |
| 关键词 | 中文楷体、西文 Times New Roman，五号，10.5 pt，黑色 |
| 图题 | 宋体或黑体，五号，10.5 pt，黑色，居中，图下方 |
| 表题 | 宋体或黑体，五号，10.5 pt，黑色，居中，表上方 |
| 图注、表注 | 宋体，小五，9 pt，黑色，左对齐 |
| 参考文献 | 中文宋体、西文 Times New Roman，五号，10.5 pt，黑色，悬挂缩进 |
| 页眉页脚 | 宋体，小五，9 pt，黑色，不使用彩色分隔线 |

字号允许根据文档篇幅和用户要求做整体调整，但必须保持稳定的层级关系。不得在同一级标题中随机混用字体、字号、颜色、缩进或段落间距。

### 5.2 标题编号

正式中文文档需要编号时，优先使用“一、”“（一）”“1．”“（1）”或阿拉伯数字多级编号。编号必须使用 Word 多级列表或程序化编号逻辑实现，不能把编号当作装饰符号，也不能使用“●”“◆”“▶”“✓”等图形充当章节编号。

标题层级必须连续。不得从一级标题直接跳到三级标题，不得出现只有一个子标题的孤立层级。标题末尾通常不加句号。

用户未要求编号且文档较短时，可以只使用无编号标题；但全文必须保持一致，不能一部分编号、一部分不编号。

## 六、正文组织规则

正文不得默认使用项目符号式分点。禁止使用“•”“●”“○”“▪”“-”“*”“✓”“✔”“→”等符号堆砌内容，也不得将完整论证拆成演示文稿式短句列表。

内容应优先写成连续、完整、具有逻辑衔接的段落。确需表达并列关系时，可在段内使用“第一，……；第二，……；第三，……。”，或者使用正式编号“1．”“2．”“3．”。只有当用户明确要求清单、检查表、操作步骤或条目式合同结构时，才允许使用 Word 的编号列表；即使如此，也默认使用简洁的阿拉伯数字编号，不使用装饰性项目符号。

每个正文段落应围绕一个中心观点展开。避免一行一句、连续空段、过短段落、聊天式问答、口号式句子和无依据的强调。段落之间通过内容逻辑和段前段后间距区分，不通过插入空白行模拟版面。

## 七、标点、引号与中西文混排

中文叙述统一使用中文全角标点。双引号使用“”，嵌套引号使用‘’。禁止在中文正文中使用 ASCII 直引号 `"`、ASCII 单引号 `'`、方向不匹配的引号或中英文引号混排。

中文句子中的逗号、句号、冒号、分号、问号、感叹号和括号分别使用“，”“。”“：”“；”“？”“！”和“（）”。破折号使用“——”，省略号使用“……”。年份范围、页码范围和数值范围优先使用规范连接号，并在全文保持一致。

英文题名、拉丁学名、基因名、文件名、路径、网址、DOI、公式和代码按各自规则保留半角字符。不得进行会破坏 DOI、URL、版本号、文件路径、基因名称或数学表达式的全局全角化替换。

中文与英文、数字之间通常不额外插入空格；数值与物理单位之间保留一个半角空格，例如“10 mL”“37 ℃”“5 mg/kg”。百分号紧随数字，例如“12.5%”。

## 八、禁止 Markdown 视觉习惯进入 Word

### 8.1 禁止引用块样式

除非用户明确要求排版一段长引文，否则不得生成灰色底纹、左侧粗线、缩进卡片或网页式 blockquote。普通引用内容应直接融入正文，并使用中文引号和规范引文标记。

真正的长引文可以使用独立段落、左右适度缩进和略小字号，但保持黑字白底，不添加边框、阴影、图标和背景色。

### 8.2 禁止代码块误用

普通术语、路径、命令名、变量名和短代码不得自动放入灰色代码块。只有用户明确需要展示程序代码时，才使用等宽字体、浅灰或无底纹的代码样式，并控制分页和行宽。非技术文档不得出现代码块风格。

### 8.3 禁止网页式强调

不得把每个关键词都加粗，不得使用荧光高亮、彩色标签、胶囊标签、信息卡片、提示框、警告框和 FAQ 折叠块。加粗只用于标题、表头、少量真正需要强调的术语或结论。

### 8.4 禁止 Markdown 表格直译

不得把 Markdown 管道表格直接转换成宽度失控、边框繁杂、彩色表头的 Word 表格。必须重新判断表格是否必要、列数是否合理、文字是否适合表格，以及页面宽度是否容纳。

当内容更适合段落时，应改写为段落；当内容适合比较时，才建立 Word 原生表格。

## 九、表格生成规范

表格默认采用简洁、正式、无彩色装饰的 Word 表格样式，仅使用黑色、白色及必要灰阶。表格单元格中作为图片对象嵌入的照片、图表或数据可视化可以保留具有信息意义的颜色；表格文字、表头、单元格背景、边框、Word 形状和非图片色块图例不得自动着色。不得默认使用彩色表头、交替彩色行、彩色图例块、渐变、阴影、圆角卡片或粗重外框。

学术论文中的数据表优先使用三线表：仅保留表顶线、表头下分隔线和表底线，线条为黑色，正文不使用竖线。报告、方案、制度和信息汇总表可以使用简洁网格表：黑色或深灰细线，白色背景，无彩色填充。

表题放在表格上方，图题放在图片下方。表题与表格、图片与图题必须保持同页。表头加粗并根据内容选择居中或左对齐；数值列按小数点或位数对齐；同一列的小数位数保持一致。

表格宽度不得超出正文版心。优先设置固定列宽或按内容合理分配列宽，不依赖“自动调整到窗口”造成跨设备漂移。长表跨页时重复表头，不允许将一个短表无故拆到两页。单元格内不使用多余空行，不使用回车模拟行高。

表格中文字默认为黑色，中文宋体、西文 Times New Roman，字号通常为五号或小五。表格不应为了视觉丰富而改变字体颜色。需要强调合计行时，可使用加粗或双底线，不使用彩色底纹。

## 十、图片、图形与题注

图片必须保持原始宽高比，禁止拉伸变形。图片默认水平居中，宽度不得超出正文版心。图片分辨率应满足打印和屏幕查看需要，不能出现明显模糊、裁切或遮挡。彩色图片默认保留原始色彩，不执行自动灰度化、去饱和、主题色映射或统一着色。

图题使用“图 1　标题”或用户指定格式，位于图片下方，黑色、居中、无彩色标签。表题使用“表 1　标题”，位于表格上方。题注应使用统一的 Word 题注样式，并与正文中的交叉引用保持一致。

除非用户明确要求信息图或品牌视觉，不得自动绘制装饰性流程图、无意义图标、复杂箭头网络、渐变模块和卡片式结构。流程图、示意图或数据图作为图片插入时可以保留必要色彩；使用 Word 原生形状、文本框、SmartArt 或图表构建时属于非图片内容，默认只使用黑色、白色及必要灰阶。不得以“好看”为由随机配色，并应保证打印可读性。

## 十一、分页、分节与版面稳定性

不得使用连续回车、连续空格、Tab 堆叠或大量空白段落控制页面位置。应使用段落间距、制表位、分页符、分节符、表格布局和样式实现稳定版式。

标题必须设置“与下段同页”，避免标题悬在页末。图题和表题必须与对应对象保持同页。正文应开启孤行控制，避免一页顶部或底部只出现一行正文。不得在页面末尾留下无意义的大面积空白，除非章节必须另起一页。

需要横向页面展示宽表时，应使用独立分节符，仅将对应页面设为横向，并在后续恢复纵向。页眉、页脚和页码必须在分节后保持连续或按用户要求重新编号。

章节另起一页时必须插入分页符，不得用多个回车“顶到下一页”。封面、目录、正文和附录需要不同页码规则时，应使用分节符和 Word 页码域实现。

## 十二、页眉、页脚、目录与域

用户未要求时，不自动添加复杂页眉。需要页眉时，使用简短的文档标题、章节名或单位名，字体小五、黑色，不使用彩色横线和图标。

页码默认位于页脚居中或右侧，使用 Word 页码域，而不是手工输入数字。目录必须基于标题样式和 TOC 域生成，不能手工敲点线和页码。图表目录、交叉引用和编号同样应优先使用 Word 域或稳定的程序化字段。

超链接在默认正式文档中显示为黑色并保留下划线或采用与正文一致的视觉样式，避免 Word 默认蓝色和访问后紫色造成非图片内容出现彩色。用户要求保留标准超链接视觉时除外。

## 十三、学术与科研文本的字符级格式

### 13.1 微生物及分类学名称

凡属级、种级及属种组合的拉丁分类学名称，必须使用真实斜体格式。属名首字母大写，种加词小写，例如 *Ruminococcus albus*。属名单独出现时仍斜体，例如 *Ruminococcus*。后文在无歧义时可写为 *R. albus*。

科、目、纲、门等高于属级的分类单元通常使用正体。菌株编号、血清型、保藏号和培养物编号使用正体，例如 *Escherichia coli* O157:H7 中，仅属名和种名斜体。未定种写作 *Bacillus* sp. 或 *Bacillus* spp.，其中属名斜体，sp. 和 spp. 正体。

OTU、ASV、MAG 编号、数据库占位名称、样本编号和基因组簇编号不得机械斜体。学名斜体规则必须应用于标题、摘要、关键词、正文、图题、图注、表题、表注和参考文献题名。

在 DOCX 中必须设置字符的 `italic` 属性，不能保留 Markdown 星号作为可见字符。

### 13.2 统计学符号

统计学变量和统计量中的单个拉丁字母按规范使用斜体。显著性概率写作 *P* < 0.05 或 *P* = 0.032，其中 *P* 必须大写并斜体。常见统计符号 *n*、*t*、*F*、*r*、*R*²中的字母使用斜体，平方数字使用上标。

SD、SE、CI、df、ANOVA、SEM 等多字母统计缩写通常使用正体。希腊字母通常保持正体，除非目标规范另有要求。不得把普通单词、化学符号、基因名称或分组名称中的字母 P 批量设为斜体。

比较符号两侧保留半角空格，数字小于 1 时保留前导零。表格中的显著性字母应使用真实上标格式，并在表注中说明比较范围和显著性阈值。

### 13.3 上标、下标与公式

化学式、数学式、单位指数、基因型和统计表达式必须使用真实上标、下标或 Word 公式对象，不得用普通字符位置模拟。复杂公式优先使用 OMML 公式；简单的平方、立方和化学下标可以采用字符级上标、下标。

## 十四、参考文献与引用

引用格式必须服从用户、学校、期刊或项目规范。用户未指定时，应先根据文档类型选择常见的顺序编码制或作者—年份制，并全文保持一致。

不得自动把引文显示成网页式引用卡片、灰色引用块或聊天系统的 citation token。文中引用应作为普通正文的一部分，采用上标、方括号或作者—年份格式。参考文献表使用悬挂缩进和统一字号。

不得虚构作者、题名、期刊、年份、卷期页码、DOI 或访问日期。涉及文献检索时，不检索、不引用 MDPI 和 Frontiers 及其旗下期刊。网页可用于定位正式来源，但普通网页、博客、自媒体和搜索结果页不得在没有规范要求时充当学术参考文献。

## 十五、文档类型适配

### 15.1 学术论文和研究报告

采用摘要、关键词、正文、图表、结论和参考文献等结构。正文通常首行缩进，表格优先使用三线表，学名、统计符号、公式和引文执行严格的字符级格式。

### 15.2 项目方案、分析报告和商业文档

采用标题、背景、目标、方案、实施路径、资源需求、风险和结论等结构。默认不使用彩色卡片和演示文稿式模块。正文和表格保持正式克制，项目图片、产品截图、数据图和示意图可以保留原始或必要色彩。表格采用简洁网格或少线表，通过标题层级和段落结构组织内容。

### 15.3 通知、函件、申请和正式说明

根据文种调整标题、称谓、正文、落款和日期。不得套用论文摘要或关键词结构。正文保持正式段落，不使用项目符号；事项较多时使用“一、”“二、”或“第一，”“第二，”组织。

### 15.4 操作手册和技术文档

允许使用正式编号步骤、代码段、命令和表格，但不使用装饰性项目符号。命令、路径和代码采用等宽字体，正文及其他非图片内容保持正式、无彩色装饰。警告和注意事项使用“注意：”“警告：”等普通段落标题，不生成彩色提示卡片。

### 15.5 简历、宣传页和创意文档

只有用户明确要求视觉设计时，才允许为文字、表格、形状和其他非图片内容引入彩色。即使进行视觉设计，也必须建立统一样式，不得随机配色或堆叠装饰元素。

## 十六、DOCX 实现要求

创建 DOCX 时优先使用 `python-docx` 建立页面、样式、段落、表格、页眉和页脚。需要目录、交叉引用、自动编号、复杂公式、文本框或其他高级 Word 能力时，可以使用 OOXML 补丁，但补丁后必须重新渲染检查。

必须显式设置东亚字体和西文字体，避免只设置 `font.name` 导致中文字体失效。正文、标题、表格、页眉页脚和题注都应设置 `w:eastAsia`。所有文字以及表格、形状、边框等非图片样式默认使用黑色 `000000`、白色或必要灰阶，不要依赖主题色；不得据此修改图片对象中的原始颜色。

不得使用 Word 内置的彩色主题表格样式。表格边框、单元格边距、表头重复、行高和列宽应程序化设置。不得依赖不同 Office 版本可能变化的“自动套用格式”。

不得将 HTML、Markdown 或富文本直接粘贴进 DOCX 后交付。内容必须被解析并重新构造成 Word 段落和 run。Markdown 的粗体和斜体只能在确有语义时转换为 Word 字符格式，Markdown 的列表、引用块和水平线不得机械转换。

应在文档属性中设置合理的标题和主题，并在最终交付前清除无关作者信息、批注、修订痕迹、隐藏文本、占位符和临时内容。

## 十七、推荐生成流程

1. 识别文档类型、读者、用途、篇幅和用户明确格式要求。

2. 将原始内容解析为语义结构，不保留 Markdown 视觉组件。

3. 从空白 DOCX 建立页面设置、字体映射和样式体系。

4. 按语义依次写入标题、正文、图表、公式、题注、引用和参考文献。

5. 对学名、统计符号、上下标、链接和强调内容执行字符级格式。

6. 清理所有 Markdown 残留、彩色文字、彩色表格样式、彩色 Word 形状、默认蓝色超链接、引用块、装饰性项目符号、空白段落和随机直接格式；此处的彩色清理仅针对非图片内容，不得误删、灰度化或重新着色图片对象。

7. 检查标题层级、编号、分页、表格宽度、图题位置、字体统一性，以及彩色图片在屏幕显示和灰度打印时的可读性。

8. 使用标准 DOCX 渲染工具将文档转换为逐页 PNG，并逐页进行视觉检查。

9. 发现裁切、错位、字体替换、表格跨界、标题孤行、图题分离、空白页、未经用户允许的非图片彩色内容或 Markdown 痕迹时，修改后重新渲染。

10. 仅在所有页面通过检查后交付最终 DOCX。

## 十八、强制清理规则

最终文档中不得出现下列问题：可见的 Markdown 标记；未经用户允许的彩色正文、彩色标题、彩色表格、彩色形状或其他非图片彩色内容；Word 默认蓝色超链接；灰色引用块；大面积装饰底纹；卡片式内容区；装饰性项目符号；无意义图标；不同段落随机字体；同级标题字号不一致；宽度超出版心的表格；图片变形；无依据地将彩色图片灰度化、去饱和或统一着色；连续空格或连续回车控制布局；手工输入的页码；手工敲出的目录点线；标题位于页末而正文在下一页；图题和图片分离；表题和表格分离；孤立空白页；批注、修订和占位符；将学名星号原样显示；将普通字母 P 全部误设为斜体。

## 十九、终检标准

| 检查项 | 合格标准 |
|---|---|
| 文档来源 | 从空白 DOCX 或用户明确指定的模板创建，不携带无关旧模板内容 |
| Word 语义 | 使用样式、段落、表格、题注、分页符和分节符，不依赖 Markdown 视觉结构 |
| 颜色 | 文字、表格、形状、边框、页眉页脚和其他非图片内容仅使用黑色、白色及必要灰阶；作为图片插入的照片、科研图、截图、地图、流程图和数据图表允许保留原始或必要色彩 |
| 字体 | 中文和西文字体明确设置，同级内容完全一致 |
| 标题 | 层级连续，字号稳定，标题与下段同页，无装饰性色彩 |
| 正文 | 连续完整段落，两端对齐，缩进和行距统一，默认无项目符号 |
| 标点 | 中文标点全角，引号统一为“”和‘’ |
| Markdown 清理 | 不存在 `#`、`**`、`>`、反引号、管道表格等可见残留 |
| 引用块 | 普通引用融入正文，不存在网页式灰色引用卡片 |
| 表格 | 无彩色主题，边框简洁，宽度合理，表头和数值对齐正确 |
| 图形 | 图片不变形、不被无依据灰度化，彩色图片保留原始或必要色彩；图题在下，表题在上，对象与题注保持同页 |
| 科研格式 | 微生物学名、统计符号、上下标和公式按语义正确排版 |
| 分页 | 无连续回车模拟分页，无标题孤行、对象分离和异常空白页 |
| 域与页码 | 目录、页码和交叉引用使用 Word 字段或稳定程序逻辑 |
| 清洁度 | 无批注、修订、占位符、隐藏文本、无关作者信息和临时内容 |
| 视觉验收 | 已逐页渲染检查，不存在裁切、重叠、乱码、文字与装饰颜色杂乱或版式漂移；图片原始色彩显示正常 |

## 二十、最终交付原则

默认只交付最终 DOCX，不交付原始模板、临时 Markdown、HTML、中间转换文件、逐页 PNG 或调试 PDF。只有用户明确要求时，才提供这些辅助文件。

交付前必须确认该文档即使在未安装特殊字体、不同 Word 版本或 LibreOffice 中打开，仍能保持基本可读和版式稳定。不能确认时，应使用常见字体、固定列宽、明确段落属性和逐页渲染验证降低兼容性风险。
