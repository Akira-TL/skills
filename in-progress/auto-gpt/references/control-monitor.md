# 持续控件采样与待办确认

仅在 `browser-access` 已选择 WSL → Windows Chrome 适配器时使用。使用已授权的 `auto-gpt` 可见浏览器；命名配置核验失败时报告事实，不重启浏览器或降级核验。

## 唯一前台进程

通过当前执行器可保留标准输入的前台终端启动；需要伪终端时启用对应选项：

```sh
bash <auto-gpt目录>/scripts/auto_gpt.sh monitor \
  --browser-access-script <browser-access目录>/scripts/browser_cdp.py \
  --endpoint <核验过的连接地址>
```

`monitor` 是正常监听入口。启动时核验身份，随后通过 `browser-access` 的页面发现和 `BrowserSession` 每分钟采样全部 HTTPS `chatgpt.com` 页面，不依赖某个固定标签页。关闭原观察页不缩小整个范围；新增、换址和关闭页面由下一次采样更新。

进程持续到收到停止请求、标准输入结束或执行器取消，不因事件、30 分钟期限或单页采集失败退出。协议请求仍有短超时。前台等待工具单次返回“仍运行”时继续同一句柄，不创建重复进程。保持可取消，不使用 `&`、`nohup`、守护进程、定时任务或状态文件。

启动返回一次 `kind: monitor-started`。后续采样静默进行，Agent 通过同一终端标准输入每约一分钟发送一行：

```json
{"op":"status","id":1}
```

返回 `kind: monitor-status`、请求标识、成功采样距今时间、**完整** `observations`、全部 `pending`、已确认的 `decisions` 和采集错误。完整范围始终包含所有页面，不能把某一个待办当成整个范围。没有待办且没有异常时，只机械续等，不读正文或作语义判断。执行器支持工具编排时可在编排层请求状态、消化稳定空结果，仅在待办、范围变化或失败时交给模型；不要为等待反复回传源码、启动命令或正文。

## 待办由代码保留

所有可能需要核对的会话进入进程内待办队列；重复状态查询和处理其他页不会删除它。相同会话的多个标签页合为一个待办，保留全部目标、草稿和失败事实。页面恢复生成时旧待办失效；采集失败保留待办但禁止确认；页面关闭后才移除其范围。

每个待办有独立 `token`。Agent 完整读取当前用户要求、停止前回复及必要前文后，可以确认本轮已完成、需要人工或错误暂停：

```json
{"op":"ack","id":2,"token":"当前待办令牌","disposition":"complete","reviewed_version":"完整读取返回的64位版本","latest_user_id":"同次读取返回的最新用户消息身份"}
```

`disposition` 仅接受 `complete`、`human`、`error`。确认必须对应当前待办令牌和同一最新用户消息，并携带完整读取的版本；陈旧令牌、旧用户指令、未知裁决或失败采样均被拒绝，不清掉待办。确认只记录 Agent 的裁决，不发送消息。判断需要续接时使用正式 `read` / `continue`，发送结果不明确先解决；新轮次或恢复生成的采样事实会撤销旧待办，不用伪造完成确认。

暂停和完成记录只属于当时的会话与控件事实。新用户消息、换会话、控件变化使旧裁决失效并重新核对，不能把旧 R2 限制带到已明确允许 R3 的新指令上，也不能把旧会话的授权请求继承给新会话。采样脚本不根据正文关键词完成、发送或暂停。

当前续接 Agent 不执行网页内的代码、合并、文件等项目指令；该限制不否定网页用户对其原任务的授权。回复提到这些操作本身不构成人工边界，必须依据网页最新要求和真实人工步骤判断。

## 故障与读取

单页采集失败不会停止其他页，旧事实带 `sampled: false`，不得作为发送证据。全局采集失败通过 `sampling_error` 返回，进程按原节奏重试，恢复后返回新事实；异常正文和聊天内容不进入错误输出。成功采样距今时间用于识别过期事实，工具句柄存在本身不证明采样成功。

正常采样只返回停止、发送／语音、输入框草稿、提示／对话框、已有消息身份等事实。断线提示只等待自然恢复，不刷新、不点重试或中止。语义正文仅在处理对应待办时按 [页面观察与单次动作](browser-operations.md) 完整读取。

## 停止与恢复

停止前先撤销后续发送，通过同一句柄请求：

```json
{"op":"stop","id":3}
```

等待 `monitor-stopped` 和进程退出。真实 `Ctrl+C`、标准输入结束或 `auto_gpt.sh stop <本观察进程PID>` 也可结束进程；保留浏览器、登录态与网页任务。

只有前台进程确已退出后才重新启动；重启时从真实页面重新核对，不把未知发送结果当成未发送。基线、待办、裁决和正文只在进程及 Agent 内存中，不写日志、临时文件或数据库。

旧 `start --stream --max-wait-seconds 1800` 仍作为兼容入口保留，其到期会退出并交接完整基线；正常持续监听使用上面的 `monitor`，不再依赖 Agent 每半小时重启。
