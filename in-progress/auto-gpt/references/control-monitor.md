# 只读控件观察

仅在 `browser-access` 已选择 WSL → Windows Chrome 适配器时使用。先通过其命名配置 `status` 核验已授权的 `auto-gpt` 实例，再用 `tabs` 找到一个真实 ChatGPT 页面作为观察连接的目标。其他执行器使用能实现同样只读控件等待的能力，不建立自动发送服务。

## 前台启动

从当前安装或待测试的技能找到脚本，运行同一版本的 `.sh` 入口：

```sh
bash <auto-gpt目录>/scripts/auto_gpt.sh start \
  --browser-access-script <browser-access目录>/scripts/browser_cdp.py \
  --endpoint <status核验过的连接地址> \
  --anchor-target <已发现的完整ChatGPT页面ID> \
  --anchor-url <该页面的准确网址> \
  --max-wait-seconds 1800 --stream
```

脚本自己再次通过 `--profile auto-gpt --timeout 30 status` 核对身份与地址，外层进程最多等待 45 秒，只在成功时导入 `browser-access` 公开的 `BrowserSession`。后续发现页面与读取控件都复用其目标锁和协议调用，不再启动浏览器、不导航、不访问认证存储；连接目标关闭或更换主文档时返回观察错误，由 Agent 重新发现后决定是否重建观察。

以执行器的前台终端会话运行；不要加 `&`、`nohup`、守护进程或持久定时任务。工具调用保持可中断，单次等待不超过执行器允许的响应边界；若工具返回“进程仍在运行”，继续等待同一会话，不另外读取正文或启动观察进程。工具调度仍可能花少量 token；此实现减少正文读取和模型判断次数，不承诺整个执行器零 token。

## 事件与重新等待

稳定空轮询只续等同一句柄。父 Agent 不每分钟催问活性，监听子 Agent 不逐分钟发送“无变化”；只有真实事件、终态或用户要求核验才交接。使用当前执行器支持的事件等待；若等待工具会定期返回，保留其取消与响应边界，仅机械续等，不能声称模型只在事件时运行。脚本、技能和长启动命令保持在源文件中，不反复展开到上下文。

执行器提供工具编排且允许保留运行单元时，可在编排层串行续等同一终端句柄，把空结果留在该层，仅在输出非空或取得退出码时交给模型。每次底层等待仍遵守响应时限，用户停止时取消等待并停止观察；编排单元的定期返回只续等该单元。只传当前句柄和少量事件，不为等待复制浏览器源码。缺少这种能力时维持机械续等并说明成本，不能另建无人接管的常驻服务。

单页连接或布局采集失败输出一次 `sampling-changed`，携带该页规范错误；重复相同错误保持安静，每分钟独立重试，其他页继续采样。旧观察保留但标为 `sampled: false`，不能当作成功采样。恢复输出 `recovered_targets` 及对应新事实；失败目标关闭时输出 `removed_targets`，移除未知记录，不伪称恢复。结束时 `sampling_failures` 列出仍失败的页面，完整 `observations` 用于内存接续。页面发现或观察锚点失败仍返回全局 `observation-error`。

单次控件等待默认最多 1800 秒，可用 `--max-wait-seconds` 指定正数。到期返回 `reason: watch-timeout`、空 `targets` 和最后一份完整 `observations`；正在进行的协议请求仍受浏览器适配器自身的短超时约束。到期只是结束本次等待，不表示聊天结束或采集失败。总体监听继续时，Agent 将返回基线原样传入下一次前台等待，不读取正文、不发送、不刷新；不并行启动第二个观察进程。掉线计时和已报告标记随基线保留，采样缺口仍按原规则处理。

每分钟采样全部真实 HTTPS `chatgpt.com` 页面。只读表达式在 `scripts/observe-controls.js` 维护，返回按钮数量、输入框和草稿是否存在、提示／对话框数量、断线提示是否存在及现有轮次标识，不返回回复、用户消息正文、模型推理或个人资料。运行状态稳定时没有输出。

已观察的中文断线提示位于 `main [role="status"] .text-chatgpt-recovery`，不是警报控件。只在该界面区域匹配完整提示，不扫描整个回复中的关键词。布局或语言改变时由 Agent 重新勘察；未知文字不伪装成已识别断线。

断线提示只影响等待，不触发专门的掉线事件或恢复动作；即使持续超过三分钟也不读正文、不刷新。恢复到发送／语音控件时才按正常结束事件核对。旧基线中的 `connection` 计时可读取，仅为兼容已有内存交接，不作为动作条件。

`--stream` 在同一前台进程持续观察：首次输出 `watch-started` 和完整控件事实，`targets` 仅列出首次需要核对的目标；后续输出 `controls-changed`、变化目标和它们的事实，关闭目标只出现在 `targets`，不在 `observations`。Agent 合并事实并保留待核对队列；不要把事件里的少量变化项误当完整范围。脚本继续采样，不等待 Agent 语义判断或负责发送。30 分钟到期输出 `watch-timeout` 和全部最新事实并退出，Agent 原样作为下一进程的 `--baseline`，同时保留待处理及发送未确认记录。旧版不加 `--stream` 时仍在首个事件后退出。

发送期间观察可能积累多个事件；先合并全部已到达的事件，优先处理结束目标，避免新增页面操作挡住续接。已处理目标的重复事件只触发事实核对，不重发。基线、队列和发送记录均只在进程及会话内存中，不能写临时文件。

同一会话的重复标签页仍全部采样，Agent 负责合并判断、保留所有草稿。Agent 已暂停的会话可使用重复的 `--ignore-conversation <URL中的会话标识>` 排除，排除作用于该会话的全部标签页；恢复由 Agent 决定。若人工边界解除证据需在页面上观察，可不排除，控件变化只触发重新核对，不自动解除暂停。

脚本的 `observation-error` 返回错误类型、规范错误码、发生阶段、失败目标及上轮成功取得的控件事实，退出码为 `2`；不输出异常正文或协议上下文。阶段包括配置核验、观察目标绑定、页面发现和控件采样，Agent 可据此有针对性地只读核对；旧控件事实不代表本轮采样成功。目标关闭或文档变化时重新发现并决定是否重建，连接超时先核验连接，不刷新或凭错误自动重发。它不是无回复判定、失败次数或错误暂停决定。未知控件或一分钟采样间隙可能漏掉短促变化，Agent 必须据当前实际页面核对，不靠次数或缺少停止按钮发送。

## 停止

用户停止、当前任务结束或 Agent 会话结束前，用执行器取消／中断当前前台终端会话，并等待其退出。终端支持时使用真实 `Ctrl+C`；如果掌握该观察进程 PID，也可调用：

```sh
bash <同一auto-gpt目录>/scripts/auto_gpt.sh stop <观察进程PID>
```

停止入口只允许结束命令行指向同一观察脚本的进程，取消退出码为 `130`；不关闭 Chrome，不点击网页停止按钮，不创建 PID 文件、状态文件或日志。执行器若无法取消自己的前台任务，就不启动这类持续观察。
