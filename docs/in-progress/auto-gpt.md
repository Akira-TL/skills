# auto-gpt

`auto-gpt` 是专用可见 ChatGPT 浏览器的会话内监听技能。你在浏览器里发任务，只读脚本每分钟检查停止、发送／语音等控件。状态没有需要核对的变化时，Agent 等待事件；出现可能结束的变化后才读取完整回复，判断是否需要发送“继续”。它不会执行回复中的下载、文件或其他任务指令。

## 使用

- “启动 auto-gpt”：开始一次监听；专用配置中没有 ChatGPT 页面时打开首页。
- “停止 auto-gpt”：停止监听，保留浏览器和登录态，不中止网页中正在运行的任务。
- “恢复 auto-gpt 的某个错误暂停会话”：由 Agent 重新检查该会话并恢复；人工障碍解除后由 Agent 核对解除证据。

所有 ChatGPT 页面都在观察范围内，同一会话的多个标签页合并处理。任务正常完成后仍等待你发起新任务。非 ChatGPT 页面不参与；用户草稿、未确认发送、需要人工或状态不明确时，Agent 会退让。

## 执行边界

减少消耗首先减少模型运行：每分钟采样留在脚本，监听者只交接真实变化或终态，取消父子之间的逐分钟催问和空状态汇报。执行器若会定期结束等待调用，模型仍可能被唤醒；安静等待不能冒充零消耗。正式入口已包含单页错误隔离，避免因某页临时连接失败反复展开临时启动脚本。重复相同错误不输出，新错误与恢复只返回对应页面；失败旧事实带 `sampled: false`，不能作为当前状态使用。

正文读取默认每段 6000 字符，返回总长、范围、下一段偏移及版本；后续段锁定同一版本，必须完整覆盖后才判断。已核验的独立长 Base64 可单列为长度和摘要，版本仍绑定其原文；需要查看时只读取指定载荷的分段内容。混合解释、错误和人工提示保持正文，未知内容不省略。常规返回省去动作坐标、长 DOM 路径及重复父容器文字。

采集失败的页面被关闭时会单次通知移除未知记录；关闭不等于恢复，也不会重开页面。

监听只在承载它的 Agent 会话持续运行时有效；会话结束后不作为后台服务继续。浏览器是可见窗口，没有另外的仪表板。默认浏览器配置保持原样，专用身份固定为 `auto-gpt`。

续接和暂停均由 Agent 判断并显式发起，不由脚本定时触发。脚本只读控件，不采集对话正文、不自动发送、不按失败次数暂停。控件状态仅在进程内存和 Agent 上下文传递，不保存本地文件。续接次数不限，连续三次真实失败也只是 Agent 的判断材料。

这种观察方式减少正文读取和模型判断次数；执行器若需要返回前台进程的运行状态，仍会产生少量工具调度 token。按钮只说明界面状态，Agent 仍需区分任务完成、时长中断和需要人工。每分钟采样不能保证捕获两次采样之间的所有短促变化。

前台观察以 `--stream` 持续输出变化事件并在内存保留基线，不在每次事件后退出；变化时只返回对应页面事实。单命令最多 30 分钟，到期才交接完整基线并重新等待。Agent 保留待核对队列，已结束目标优先，新增／替换页面不会覆盖未处理任务或发送未确认记录。协议请求仍有短超时；长时间测试不靠中止或刷新真实任务制造负载。

“连接已中断，正在等待完整答复”只等待自然恢复，不因持续时间触发正文读取或刷新。恢复到正常发送／语音状态时，才按结束事件阅读回复。用户明确委派监听时，可由短上下文子智能体专门负责；交接先停止旧观察，仍只有一个接管者。这能隔离开发上下文，不能承诺执行器等待完全不花 token。

本技能不选择或使用 Pro 模型，不为了测试中止或反复刷新真实任务。机械输入会在执行前再次检查页面和草稿，并在发送后确认新消息；这不代表网站提供了人与 Agent 的互斥锁。

只读回复提取支持把经 Agent 核验的界面控件和机械载荷单列：回复仍完整返回，载荷默认仅返回长度与摘要、按需读取全文。界面按钮文字变化不再触发整段重读，回复或载荷变化仍使版本失效；无法分清内容时保留全文。四项独立本地 Chromium 场景验证了完整回复、界面变化、载荷变化及未知布局拒绝，不改真实任务页面来测试。

正文提取保留 `display: contents` 容器下的可见子节点和显式换行，避免容器自身没有矩形时漏掉整段说明；独立本地页面另有对应覆盖。

真实页面进一步确认助手活动根容器也使用 `display: contents`。根容器以其实际可见后代或直接文字判断可见性，保留唯一性约束，不把没有自身矩形误判成缺少回复。

Agent 明确判断续接后，可用 `auto_gpt.sh continue` 发起一次动作：在一个受保护连接中聚焦、插入精确的“继续”、真实回车并确认新的用户消息。版本、模型、草稿或生成状态变化时退让；结果不明不重发。`read` 使用同样的已核验选择器完整读取，界面布局不匹配时先调查。单次动作确认只返回少量事实，下一回复结束前继续由只读控件脚本等待。

观察启动、正文读取和单次动作共用身份核验：浏览器查询显式等待最多 30 秒，外层进程最多等待 45 秒，容纳 Windows 进程查询超过原 15 秒默认值的情况。超时或实例身份不符仍拒绝操作，不重启浏览器、不绕过核验，也不自动重试发送。

采集失败返回规范错误码、发生阶段和失败目标，不返回聊天内容或协议上下文；Agent 可只读核对相应连接或目标，避免只看到错误类型就重查全部页面。失败结果中的控件事实属于上一轮成功采样，不能当作当前页面已经完成。

时长中断可能发生在工具活动期间，页面没有最终总结也可能已有真实进展。Agent 完整读取这些内容后判断续接，不把缺少固定标题当作无回复失败；新入口尚未适配布局时保留原有公共会话的严格保护路径。

单次读取和动作同样返回规范错误码，区分选择器未匹配、多个匹配与范围重叠；保持唯一性要求，避免仅凭异常类型反复读取整页来猜原因。

发送后只读用户消息与控件进行机械确认，允许网站替换旧回复容器。虚拟历史计数没有增加时保留未确认状态，由 Agent 立即回读新轮次或确实新出现的回复；不重复发送，也不把正在生成或输入框空当作提交证明。

## 本地测试

测试直接读取当前仓库中的 `in-progress/auto-gpt/SKILL.md` 和 `productivity/browser-access/SKILL.md`，使用同一源码仓中的浏览器执行入口。不要把全局已安装的旧版本当成待测版本；本地测试不以推送 GitHub 或更新 Skiloom 安装为前提。

从本仓根目录核对已有专用窗口，不启动新窗口或发送消息：

```sh
uv run --no-project --offline productivity/browser-access/scripts/browser_cdp.py --profile auto-gpt status
```

浏览器机械测试也可以直接本地运行：

```sh
uv run --no-project --offline -m unittest discover -s productivity/browser-access/tests -p 'test_*.py'
```

控件观察的聚焦测试：

```sh
uv run --no-project --offline -m unittest discover -s in-progress/auto-gpt/tests -p 'test_*.py'
```

`--offline` 要求所需依赖已存在于本机缓存。真实页面观察与单次续接仍由读取上述两个本地技能的 Agent 执行，测试命令不会自动续接。
