# literature

`literature` 围绕当前 Active Uncertainty 执行文献发现、全文阅读、论文重建、批判性评估和跨论文证据综合。

默认工作模式是科研发现（Discovery），目标是找到关键方法、矛盾、边界条件和下一条判别性证据，而不是冒充系统综述。检索源按学科与任务选择，可组合 PubMed / NCBI、Europe PMC、Web of Science（WoS）、Scopus、Google Scholar、OpenAlex、Crossref、预印本与数据/代码仓库，不依赖单一检索入口。当当前 Active Uncertainty 已经形成主要 Claim、竞争解释、preferred mechanism / method 或倾向路线时，conceptual saturation 前还会主动执行以推翻、削弱或限定当前判断为目的的反证/边界检索，寻找相反结果、失败复现、negative/null evidence、boundary case 和 method critique；零命中也保存真实检索记录，但“没搜到反证”不会被解释成“反证不存在”。

论文机器原始件统一保存到 `.research/artifacts/papers/<paper-id>/`；XML、HTML、补充表格等不出现在人类 `literature/` 阅读区。人类阅读文件稳定放在 `literature/papers/` 根层，只保留按“论文题名 - 第一作者 - 年份”命名的 Markdown 与可选 PDF；主题/状态集合用 `literature/collections/*.md` 建索引。待读、已读、阅读优先级和 Critical Audit 状态都由数据库表达，不再通过 `to-read/read` 目录移动。

人类 Markdown 进入 Git。新生成或由 Agent 实质重写的 sidecar 使用 `akira:literature-note:v1` 固定格式：唯一一级标题写原始论文题名，文件头固定展示中文译题、第一作者、期刊/会议、年份、DOI、PMID/PMCID、Paper ID、论文类型、当前阅读用途和本地全文；正文的固定二级标题及顺序由阅读协议定义，三级及更深层标题可按论文类型展开。顶部与结尾各提供一个“我已阅读并确认当前版本”复选框，任意一个被勾选后由 `research-db sync-user-reading` 同步。文末 `akira:user-notes` 是用户专属区，Agent 只初始化边界，之后不修改、整理、总结或清空其中内容。阅读确认的 Git content OID 会把复选框状态和用户专属笔记都归一化，因此用户继续补写自己的笔记不会让已确认状态失效，而 Agent 更新自己的阅读正文仍会使旧确认自动失效。历史旧格式 sidecar 继续兼容；一旦迁入 v1，就完整遵守固定结构。用户确认与 Agent 的 Reconstruction / Critical Audit 分开，不作为 Literature completion 条件。人类 PDF 只是方便阅读的视图，默认不进入 Git。

阅读前先明确目的，再决定章节顺序：背景知识构建、前沿跟踪、方法学习、研究设计学习、证据核验和写作结构学习可以采用不同入口。研究设计与方法学习会主动追踪基础工作、代表实现、后续改进和边界条件，也允许跨领域寻找可借鉴方案，但必须比较推断单位、数据结构、测量误差、约束条件与关键假设，不能仅因表面相似就迁移方法。发表时间、被引次数、作者或期刊声望、引文网络连接度只作为发现与排序信号，不替代证据质量判断。

完成阅读后的 Markdown 固定使用三句话总结、为什么值得读、论文逻辑、方法拆解、实验逻辑、数据直接结果、作者解释、证据评估、关键图表与定位、可复用内容、科研启发、结论边界和我的笔记等二级标题。机械门禁只检查一级标题、固定书目信息字段、二级标题顺序、用户笔记边界和双确认框，不要求固定字数、实验数、图表数或启发数。它不是逐段摘要或缩短版文献综述，而是用于以后快速恢复“为什么重要、关键证据在哪里、能支持到哪里、下次该跳到哪里”。相关论文原则上进入全文获取与阅读流程，Observation、作者 Claim 与 Agent 的 Critical Audit 分开保存。Critical Audit 除常规 confounding、selection bias、statistics 和 mechanism leap 外，还会在实际适用时检查 success-only / survivorship selection、结果后改变 outcome / success criterion / subgroup definition、aggregate→individual 跨推断层级、缺少合理 base rate / comparator 以及关键概念在论证中偷换定义等推理失败；不为凑逻辑谬误标签制造 Issue。跨学科或跨 measurement literature 做综合前先核对 construct、operational definition、unit of inference、measurement target、causal level 与关键假设；无法建立可辩护映射的 framework 并列保留为不可直接比较，而不是为了得到一个统一故事强行合并成假共识或假冲突。若论文已经入库后才获得补充材料或其他新 artifact，使用 `research-db add-paper-artifacts` 追加到既有 Paper；若此前已经完成阅读，该 Paper 会重新进入增量 Reconstruction 与 Critical Audit，避免晚到附件游离在 canonical provenance 或既有审阅状态之外。

正式系统综述（Systematic Review）、范围综述（Scoping Review）和荟萃分析（Meta-analysis）使用独立 `SYSTEMATIC` 方法学路线，不由普通 Discovery 冒充。开始正式筛选前先由 `design` 冻结 Review protocol，包括 Review Question、eligibility、information sources、search strategy、screening、extraction、study-level appraisal 与 synthesis plan；`literature` 按 protocol 保存可复现 Search Run、deduplication、screening 和 full-text exclusion reason。需要结构化或定量综合时，把 study-level extraction 提升为 canonical Dataset；Meta-analysis 作为正式 `analysis` 执行，最终 evidence boundary 由 `interpretation` 形成。具体 protocol registration、screening reviewer 数量、risk-of-bias 工具、certainty framework 和 reporting guideline 通过 `research-standards` 从当前领域权威来源核验，不把 PICOS、RoB 2、GRADE 或“至少两个数据库”等某一方法家族要求硬编码成所有 Review 的通用规则。SYSTEMATIC 的完成依据 frozen protocol 与 search/screen/extraction/synthesis 闭合，不使用普通 Discovery 的 conceptual saturation 冒充系统检索完整性。
